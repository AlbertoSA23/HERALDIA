# Atlantis — Phase 0: analysis and questions

Status: **built and tested on a dedicated server**; the visual look is pending screenshots from the owner's game. Below are the phase 0 analysis, the answers and, at the end, what was built and what was checked.
Id `heraldia:unicas/atlantida`, generator in `tools/gen/uniques/atlantis/`, Java in `io.github.albertosa23.heraldia.unicas.atlantida`.

How each thing was checked:
- **Code**: read in the Minecraft 26.3 sources generated by Loom (`./gradlew genSources`); class and method are cited.
- **Server**: tested on a real Fabric 26.3 dedicated server with the mod's `.jar` (the same base as the smoke test).
- **Estimate**: my own calculation, not measured. Stated explicitly.

## 1. Real maximum size

What the code says:
- `ChunkGenerator.createReferences`: each chunk looks for structure starts in the chunks within **±8** around it (`range = 8`), and `ChunkPyramid` requires `STRUCTURE_STARTS` at radius 8. A piece that falls more than 8 chunks from its start chunk **is never placed** (no chunk sees it), with no error.
- Therefore a start covers at most **17 × 17 chunks = 272 × 272 blocks**. The jigsaw stops at a radius of 116 (≈ 232-248 per side). A custom Java type gains little per start (272 against ~240).
- The real limit is overcome with **several starts**: a custom placement that marks as structure chunks a lattice of chunks around an anchor (a "district" every 16 chunks = 256 blocks, with the start in the center, so that everything stays within ±8). The districts fit together seamlessly because the complete plan is designed in Python at once and split up. With this **there is no horizontal engine limit**; the limit is content, `.jar` size and available ocean.
- Vertical: the world goes from y = −64 to 319 (384). Under the water there is from y ≈ 62 (sea level 63) to the bottom (deep ocean ≈ y 30-45), and you can dig below the seabed down to y ≈ −55. Usable submerged: **≈ 100-115 blocks high**.

Possible sizes:

| Option | Districts | Footprint | Chunks | Reference |
|---|---|---|---|---|
| A | 1 | ≈ 270 × 270 | ≈ 290 | somewhat larger than an ancient city |
| B | 3 × 3 | ≈ 770 × 770 | ≈ 2,300 | ~13 times the side of an ocean monument (58) |
| C | 5 × 5 | ≈ 1,280 × 1,280 | ≈ 6,400 | needs an ocean > 1,500 wide |

Cost (estimate, not measured):
- Generation: the cost is per chunk and only when generating it. Each chunk walks the blocks of the templates that touch it; with templates of up to 48 × 48 it is comparable to an ancient city or trial chambers. There is no per-tick work.
- Runtime memory: the list of pieces is stored in each district's start chunk (hundreds of pieces per district, like a large village). Templates are loaded when used; I have not checked whether the template manager frees them afterwards.
- Mod size: today the `.jar` weighs 4.2 MB with 1,854 templates. With a modular kit (rooms and corridors that repeat) option B should add a few MB; a city with no repetition at all would be considerably heavier.
- World: B takes ≈ 2,300 chunks if explored entirely (like any explored area of that size).

## 2. Exactly one per world, in a large ocean

What the code says:
- `ChunkGenerator.findNearestMapStructure` (used by `/locate` and treasure maps) **only handles `ConcentricRingsStructurePlacement` or `RandomSpreadStructurePlacement` placements** (`instanceof`). A custom placement of another type would generate fine but `/locate` would never find it.
- `RandomSpreadStructurePlacement.getPotentialStructureChunk(seed, x, z)` is public and overridable, and only receives the seed.
- `ChunkGeneratorStructureState.hasBiomesForStructureSet` discards the set in dimensions without its biomes (the Nether and the End have no oceans).
- `Structure.generate` validates the biome at the start point against the structure's `biomes`.

Proposed design:
1. Custom placement type `heraldia:mundial`, **a subclass of `RandomSpreadStructurePlacement`**: `isPlacementChunk` returns true only on the districts' start chunks; `getPotentialStructureChunk` always returns the central district, so `/locate` and maps find it at the first step. No frequency, no configuration: always 1.
2. Anchor search, once per world and off the server thread: biomes are sampled on a grid (every 64 blocks) with the world's real biome source (it also works with biome mods), the distance to the coast is computed for each ocean cell and the **deep ocean** basin closest to 0,0 is chosen that meets: enough width for the footprint plus a margin, a minimum distance from the origin and **ungenerated chunks** (it checks whether the region files of the footprint exist; that is what makes it work in an already existing world). Estimate: ~100,000 samples, on the order of a second.
3. The chosen position is **saved in the world data**. Reason: if the modpack (biomes) or the explored map changes, a "memoryless" calculation could give another spot and a second Atlantis would appear. Saved, it is exactly one forever.
4. If there is no valid basin nearby: the radius is widened by rings (up to ~12,000 blocks), then the criteria are relaxed (normal ocean, smaller basin) and, as a last resort, the best ocean found is taken and a warning goes to the log. One is always generated.
5. Existing world: it only appears in new chunks (hence the region filter). `/locate structure heraldia:unicas/atlantida` works from any point and dimension with an ocean.

Not checked yet (to be tested while building): that the anchor is computed before the first chunk is generated at startup (the biome source is obtained when the world loads; generation threads wait for the result), and `/locate` end to end with the custom placement.

The generator already allows it: `STRUCTURE["placement"]` replaces the configurable grid (it is on `develop`).

## 3. Watertight areas under water

Code (`StructureTemplate.placeInWorld`, `JigsawStructure`): by default pieces use `apply_waterlogging`: every waterloggable block placed where there was water becomes **waterlogged** (and a waterlogged block is a source that floods the neighboring air). With `liquid_settings: ignore_waterlogging` the template's state is respected.

**Real server test** (natural generation, not `/place`): two identical test structures in a deep ocean, one with each setting: an 11 × 9 × 11 prismarine box with a dry room (ladder, stairs, slab, chest, torch, lantern), an adjoining flooded room separated by a door, a glass pane window, a "moon pool" in the floor (water below, air above) and an opening to the ocean. It was found with `/locate`, generated with `forceload`, and the blocks were read after 30 s and after 2 min:

| Check | `ignore_waterlogging` | `apply_waterlogging` |
|---|---|---|
| Air cells still dry (2 min) | **7 of 7** | 4 of 7 (flooded) |
| Waterloggable furniture dry | all of it | the lantern got waterlogged and flooded the room |
| Closed door between flooded room and dry room | holds | holds |
| Moon pool (water under air) | the water does not rise | — |
| Flooded room and waterlogged stairs from the template | with water | with water |
| After breaking a ceiling block (60 s) | 3 of 7 cells with water | more water |

Conclusions:
- Placed air **stays dry** with `ignore_waterlogging`, full-block walls and explicit water in the template wherever water is wanted. Flooded pieces carry their water and their `waterlogged=true` blocks in the template.
- **No mechanical airlocks are needed.** Water/air transitions are solved with moon pools (going up from the water into a dry room), doors (they are not waterloggable: they hold the water back) and siphons. They are also the natural resource for puzzles.
- Breaking an outer wall **floods the room** (vanilla behavior, not avoidable without mixins). Design mitigation: double walls in key rooms and the elder guardian's mining fatigue (see 4).
- Nuances of the test: the box ended up partly embedded in the seabed; the ceiling was under water (which is why it flooded when broken), but I cannot guarantee that the window faced open water. The door and the moon pool were against template water. Unsupported blocks and sand or gravel over gaps will be watched in the audit.

## 4. Defending mobs

Code:
- `Guardian.checkGuardianSpawnRules`: it spawns in water with water below; with a spawner it works even if the block is not water. `Drowned.checkDrownedSpawnRules`: with a spawner always valid. Vanilla spawners work under water for both.
- `ElderGuardian`: every 60 s it applies **mining fatigue III for 5 min to players within 50 blocks** and stays within a radius of 16 of its spot.
- The structure's `spawn_overrides` (like the monument): natural spawning of guardians inside the box, **limited by the server's mob cap**, so it cannot overload it; in exchange they respawn (and can be farmed, just like in a monument).

Proposal (for option B; it scales with the size):
- Natural guardian spawning in the flooded areas (`spawn_overrides`), with no fixed cost.
- **40-60 spawners** in groups (guardians in flooded rooms, drowned in corridors and dry rooms), only active with a player within 16 blocks.
- **80-120 placed defenders**, named and persistent: drowned with tridents (in vanilla only 6 % carry one), some with armor; guardians at chokepoints. They only exist in loaded chunks.
- **3-5 elder guardians** in the key districts (not in the whole city: covering it entirely would need ~40).
- **Final guardian**: a named boss in the antechamber of the treasure chamber (an elder guardian boosted by attributes, escorted by elite drowned with tridents). All with vanilla NBT.

Not checked: trial spawners (`trial_spawner`) with aquatic mobs; they will be tested before deciding whether to use them instead of the classic ones.

## 5. Loot

Checked against the 26.3 registries: `trident`, `conduit`, `heart_of_the_sea`, `nautilus_shell`, `diamond_nautilus_armor`, `diamond_spear`, `turtle_helmet`, `tide_armor_trim_smithing_template`, `vault` and the enchantments used all exist.

Premium chest (proposal):
- **"Poseidon's" trident**: Loyalty III, Channeling, Impaling V, Unbreaking III, Mending.
- **"Tides" trident**: Riptide III, Impaling V, Unbreaking III, Mending.
- At their level: an already crafted conduit, 2-3 hearts of the sea, 2 enchanted golden apples, a totem of undying, a turtle helmet with Respiration III + Aqua Affinity + Protection IV, diamond boots with Depth Strider III, diamond nautilus armor, an enchanted diamond spear, Tide trim templates, a disc and sponges.
- **No netherite or elytra.** No mace or heavy core either (proposal).

Does it break progression? Tridents cannot be crafted (8.5 % of the drowned that carry one) and those enchantments can be obtained with an anvil: the chest **saves a long grind, it gives nothing unreachable**. The strongest items are the totem and the apples, both already obtainable. It is higher than the rest of the unique structures, as requested.

Smaller chests: advanced sea-themed loot (diamonds, emeralds, Respiration/Depth Strider/Aqua Affinity books, nautilus shells, water breathing potions, prismarine, a very rare unenchanted trident), with each chest's extra marked `solo_sin_lootr`.

Lootr and the "unique" chest: Lootr turns chests with a loot table into per-player chests. A chest with **fixed contents** (no table) is not converted: it is truly unique. See question 3.

## 6. Summary of risks

- The world placement and the district structure are custom Java (placement, structure type and ocean search): it is the riskiest part and the first one to be built and tested.
- Without screenshots from the owner's game the look is not accepted.
- The smoke test will have to be extended: `/locate`, natural generation of at least one district and a check of the dry rooms.

## Questions for the owner

1. **Size.** A (≈ 270 × 270), **B (≈ 770 × 770, recommended)** or C (≈ 1,280 × 1,280). B is huge, fits in most large oceans and can be filled with quality content; C forces a lot of repeated filler and sometimes there will be no ocean where it fits.
2. **Visibility.** Fully submerged (**recommended**: roof under the water, only hinted at night by the glow of the domes; reached with `/locate` or a map) or with a spire or lighthouse sticking out above the sea as a landmark?
3. **Premium chest and Lootr.** (a) **A fixed-content chest, truly unique: the first group to arrive takes it (recommended, it is what you asked for)**; (b) a loot table: with Lootr each player would get their 2 tridents; (c) a vanilla vault (`vault`) with a hidden key: each player opens it once.
4. **Walls and mining fatigue.** Breaking a wall floods the room and this cannot be prevented in vanilla. Is it enough to have **elder guardians in the key districts** (mining fatigue: you cannot dig there, you have to solve the puzzles) and accept that elsewhere you can dig and flood (**recommended**), or do you prefer elders throughout the city?
5. **Legendary loot.** Do you agree with the list in point 5 (maxed tridents, conduit, totem, enchanted apples, aquatic diamond gear; **no netherite, elytra or mace**)? Say if you want to remove or add anything.
6. **Location.** I recommend: **1,500 blocks or more from 0,0**, in the nearest valid deep ocean basin (it may be far, up to ~12,000 blocks if the seed has no large oceans nearby), only in unexplored territory, and **saving the position in the world data** to guarantee there are never two. Do you agree with those three things?

## What was built

Plans and renders in `docs/unicas/atlantida/` (regenerated with `cd tools/gen && python3 -m unicas.atlantida.planos ../../docs/unicas/atlantida`).
In the plans: blue = water, yellow = air (dry area), greens = prismarine, gray = stone plinth.

### How it is generated
- **Placement `heraldia:mundial`** (Java, extends `random_spread`): the structure chunks are the nine district starts (anchor ± 16 chunks). `/locate` and maps always get the central district.
- **Anchor** (`AtlantisAnchor`): when the Overworld loads, on its own thread, biomes are sampled every 64 blocks within ±12,288 and the center closest to 0,0, 1,500 blocks or more away, is chosen by tiers: all ocean within ±448 with a deep center and unexplored; all ocean unexplored; almost all ocean unexplored; almost all ocean; the one with the most ocean. It is saved in the world's `data/heraldia/atlantida.json`. "Unexplored" = no region file exists under the footprint.
- **Structure `heraldia:atlantida`**: each district first places the **base piece** (by columns, without templates: water over the ground up to y = 62, paving with the avenues in a cross, a stone plinth down to the seabed, a circular wall of radius 372 with four gates and 18 % of its stretches in ruins) and then the 32 × 32 **tiles** that belong to it. No biome check: it always comes out whole.
- **Plan** (`tools/gen/uniques/atlantis/`): the city is built in a single voxel map (731,000 blocks, 104 entities) and cut into 391 tiles aligned with the districts, so no piece crosses a boundary. `liquid_settings` is always `ignore_waterlogging`; each waterloggable block is marked according to its surroundings (waterlogged if it touches water and does not touch air).
- **Other structures**: the two mixins the mod already had reject any other structure whose start falls within 444 blocks of the center (in the first test a vanilla ocean monument spawned inside the city).

### Levels (absolute y)
| Level | y | Contents |
|---|---|---|
| L1 | 37-58 | dry upper floors, domes, towers, temple (its dome reaches y = 58) |
| L0 | 31-36 | paving (y = 31), flooded streets and squares, ground floors |
| L−1 | 13-20 | dry vestibule under the temple and galleries: four radial ones under the avenues and a square ring 312 per side, in alternating dry and flooded 24-block stretches separated by doors |
| L−2 | −14-5 | dry staircase, antechamber, the final guardian's hall (flooded, 33 × 33 × 12), treasure (dry) and the hidden crypt of the premium chest |

### Layout
- Center: **acropolis** (a three-step base of radius 62, a colonnade of 24 columns, a cella with a glass dome and a glass shaft going down to the vestibule).
- Eight distinctive districts, one per heading: **N agora** (an arcaded square, trident statues, a dry council house with the signs explaining the seals, a ruined market), **NE artisans' hall** (dry, with a hidden basement under a covered trapdoor), **E baths** (a flooded frigidarium with a dome, a dry tepidarium, a caldarium with a magma floor and a bubble elevator to a dry gallery), **SE arsenal** (a walled compound with towers, a flooded courtyard, a dry keep with a trap corridor, an armory, a booby-trapped chest and the seal chamber behind a lever hidden under a tapestry), **S sunken harbor** (broken docks, four wrecks), **SW coral gardens** (five broken domes and an intact dry greenhouse), **W academy** (two dry library wings; the seal chamber behind a combination door whose four clues are spread across the wings), **NW amphitheater** (stands, an arena with six spawners under grates and the seal chest).
- Between them, **372 plots** on a 24-block lattice, symmetric about both axes: 204 dry houses (a dry ground floor with a door, or a dry upper floor reached by diving through a moon pool), 29 flooded houses, 46 towers with a dry upper room, 51 shrines and 42 ruins.
- Condition: **19.3 % of the built surface in ruins** (audited between 15 and 20), concentrated towards the harbor and the gardens.

### Progression, puzzles and traps
1. Three **seals** (arsenal, academy, amphitheater): each chest gives a named key and there is a sign with a digit; the fourth digit is in the baths' upper gallery.
2. In the temple's cella you go down the shaft to the **vestibule**: the three keys open three locked **arks** (`lock`) with loot for the fight, and the four digits are the position of the **four levers** that open the iron door to L−2.
3. **Poseidon's Guardian** (an elder guardian with 240 health, scale 1.5 and four drowned hoplites): when it dies it drops **Poseidon's Key**.
4. Behind its hall is the treasure; in the corner, a trapdoor under a carpet goes down to the crypt of the **premium chest**, locked with that key.
- Mechanisms: two combination doors (inverting torches and a shared "something is wrong" line), a door with a hidden lever, arrow and water dispensers next to pressure plates (in the arsenal and in the dry galleries), a trapped chest over TNT, magma bubble columns (pull down) and soul sand ones (push up).
- Hidden rooms: the artisans' hall basement and the premium crypt (both through a covered trapdoor: nothing has to be broken).

### Defenders
- Natural guardian spawning in the whole box (`spawn_overrides`, limited by the server's cap).
- Placed and persistent: 62 lookouts (guardians), 33 drowned with tridents (the "hoplites", with 40 health and armor), 3 elder guardians (arsenal, amphitheater, temple) and the final guardian.
- 48 spawners (drowned in dry areas and flooded houses, guardians in flooded areas).

### Loot
- 185 chests and barrels. Tables `menor`, `media`, `tesoro`, `arca` and `sello_*`, all with an extra `solo_sin_lootr` pool.
- **Premium chest, fixed contents (it has no table: Lootr cannot convert it)**: Poseidon's Trident (Loyalty III, Channeling, Impaling V, Unbreaking III, Mending), Trident of the Tides (Riptide III, Impaling V, Unbreaking III, Mending), a conduit, 3 hearts of the sea, 2 enchanted golden apples, a totem, the Helm of the Depths (turtle), the Boots of the Current (diamond), Triton's Spear (diamond), diamond nautilus armor, 2 Tide templates, a disc, 8 sponges, 16 nautilus shells, 12 diamonds, 4 emerald blocks, 8 gold blocks and 32 bottles o' enchanting. No netherite, elytra or mace. With the option `unicas.atlantida.cofre_unico_por_jugador` (`false` by default) each player opens their own copy (`loot/CofrePorJugador.java`; the chest carries the `custom_data` mark `heraldia_cofre_unico`).

### Audit (a condition for generating; `audit.py`, about 15 s)
- **Watertightness**: no air cell, nor any block that water breaks (redstone, levers, plates, carpets), touches water or a waterlogged block from the sides or above, nor natural terrain.
- **Supports**: ladders, signs, tapestries, levers and torches with a wall behind; doors, dust, plates and beds on solid blocks; sand and gravel with a floor; kelp with a base; bubble columns with their block.
- **Reachability**: a walk from the open sea swimming, walking, jumping one block, via ladders, doors and trapdoors, without breaking anything: it reaches every marked dry cell, the 185 chests, the spawners, the two hidden rooms, the final guardian and the premium chest.
- Valid items in the fixed chests and a ruin percentage between 15 and 20.
- The generic `lint.py` audit is not applied to the tiles (they would see half a building): that is why the plan is audited whole.

## What was checked and how

On a real Fabric 26.3 dedicated server, with the built `.jar` and a new world (seed `heraldia`):
- Anchor computed in about 2 s; on restart the saved one is read. `/locate structure heraldia:unicas/atlantida` returns the anchor.
- **The whole city generated by worldgen** (the 9 districts, about 2,300 chunks forced at once) in 56 s; the server warns about lag meanwhile, as with any mass generation.
- **The 364 marked dry cells are still air and the 154 moon pool cells are still water** one minute after being generated.
- **Both combination doors** (academy and vestibule) only open with the correct combination and close when it is broken; the arsenal door opens with its lever.
- Premium chest: contents and lock read with `data get`. Final guardian present; when killed, the key appears with its data.
- With the exclusion, inside the city there are exactly the plan's 4 elder guardians (before, 7: three were from a vanilla monument).
- The official smoke test repeats the essentials in the central district (`tools/gen/uniques/atlantis/smoke.py`).

Not checked:
- **Nothing has been seen in the game**: look, scale, lighting and gameplay need screenshots and a play session from the owner.
- The locks and mechanisms have not been operated by a player: the locks were read as data and the levers were moved with `setblock`, "touching" the adjacent blocks afterwards (what the game does when they are flipped). Arrow, water and TNT traps, the bubble elevator and the spawners: generated and audited, not fired.
- Lootr: it has not been tested with the mod installed that it leaves the fixed-content chest intact.
- Per-player chest (`unicas.atlantida.cofre_unico_por_jugador`): the logic has been tested with two and three simulated players (`CofrePorJugadorTest`) and the chest's mark on the server (smoke test), but it has not been opened with real players or with Lootr installed.
- Already existing world: the filter of explored regions is written but has only been tested in a new world. Seeds without large oceans (tiers 1 to 4 of the search) and biome mods have not been tested either.
- In the test, loose floating kelp appears (about 170 in the whole area, also outside the city); I have not determined whether it comes from the game or from the cut of the base piece at the edge.
- Performance with real players and memory with the whole city loaded: not measured.

## Changes from the proposal
- The districts are not the nine 256 × 256 cells (the corner ones fall almost outside the circle): they are eight sectors by heading around the acropolis. The nine cells are still the structure starts.
- The galleries do not connect with basements in each district: they are entered through nine shafts with a shrine (eight ring junctions and the temple's).
- The maximum length of diving without air is not audited: the city is designed to be explored with water breathing or using the dry houses as shelter.
